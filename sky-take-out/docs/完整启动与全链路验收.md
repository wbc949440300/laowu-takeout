| 2    | Redis             | 6379 | Windows 服务，开机自启                                       | 一般不用管                        |
| 3    | **Java 后端**     | 8080 | IDEA → 运行 `com.sky.SkyApplication`；失败时按下方 JAR 方式启动 | `/health` 返回 HTTP 200 |

### 首次启动：数据库初始化（必做）

若 `sky_take_out` 库为空（菜品/分类列表为空、管理端登录无数据），先导入初始化脚本（含建表+初始数据）：

```powershell
cd D:\IDEA\laowu-takeout\sky-take-out
# 先确保库存在：CREATE DATABASE IF NOT EXISTS sky_take_out DEFAULT CHARSET utf8mb4;
mysql -uroot -p sky_take_out < db-init\001-schema.sql
```

> 注意：脚本含 `DROP TABLE IF EXISTS`，重复执行会清空已有业务数据；请勿在生产库执行。
> 若后续变更了 `DishVO` 等被 Redis 缓存（JDK 序列化）的类结构，需同步清理 Redis 中 `dish_*` 旧缓存键，否则反序列化失败导致菜品接口 500。

### Java 启动失败时的备用方式

如果 IDEA 从 Maven 聚合项目启动时报“找不到主类”，在 `D:\IDEA\laowu-takeout\sky-take-out` 执行：

```powershell
mvn -pl sky-server -am package -DskipTests
java -jar sky-server\target\sky-server-1.0-SNAPSHOT.jar --spring.profiles.active=dev
```

看到 Tomcat 监听 `8080` 后再继续启动 Agent 和前端。

### 启动后统一检查

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object { $_.LocalPort -in 3306,6379,8000,8080,8888 } |
  Select-Object LocalPort,OwningProcess | Sort-Object LocalPort
Invoke-WebRequest http://127.0.0.1:8080/health -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:8000/health -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:8000/ready -UseBasicParsing
```

预期端口为 `3306、6379、8000、8080、8888`；Agent `/ready` 的 `model_configured`、`java`、`checkpoint` 应为 `true`。

## 第三部分：管理端体验（商家）⭐重点

管理端有**两种入口**，推荐用图形化的 `sky-web`：

### 方式一：图形化管理后台（推荐）`sky-web`
```
浏览器打开 http://localhost:8888
    ↓
登录 admin / 123456
    ↓
左侧菜单：订单管理 / 菜品管理 / 套餐 / 员工 / 数据统计 …
```
**优势**：
- ✅ **实时收到催单/来单通知**（连了 WebSocket，右上角弹提醒）——这是 `doc.html` 做不到的
- ✅ 接单/派送/完成都是点按钮，不用手写 JSON
- ✅ 退款、优惠券、员工管理都有图形界面

### 方式二：接口测试页 `doc.html`
```
浏览器打开 http://localhost:8080/doc.html → 管理端分组 → 登录拿 token
```
> 注意：管理端所有接口请求头要带 `token`（不是 Authorization），登录接口返回的 `token`。

### 处理顾客订单（参数规范 ⚠️易错）
| 操作 | 接口 | 参数位置 |
| ---- | ---- | -------- |
| 接单 | `PUT /admin/order/confirm` | Body: `{"id":订单id,"status":3}` |
| 派送 | `PUT /admin/order/delivery/{订单id}?riderId=1` | **Path** 传订单id，**Query** 传骑手id |
| 完成 | `PUT /admin/order/complete/{订单id}` | **Path** 传订单id |

> ⚠️ **Path/Query 别搞混**：`/delivery/{id}` 的订单id 填在 **Path 区**，`?riderId=1` 填在 **Query 区**。填错会报"订单状态错误"。
> 状态流转：**待接单(2)→已接单(3)→派送中(4)→已完成(5)**，不能跳步（没接单就派送会报错）。

### 退款审核（重点 🔄）
```
① 顾客申请退款（小程序详情页点"申请退款" / 客服说"我要退款"）
② 管理端查看：GET /admin/order/refund/list（或 sky-web 退款菜单）
③ 管理端审核：PUT /admin/order/refund/handle  body: {"id":退款申请id,"status":1,"handleRemark":"同意"}
④ 同意后 → 订单自动变"已取消" ✅（顾客再进详情看到"已取消"）
```
> 说明：**申请退款 ≠ 立即取消**。申请只是提交等审核，商家同意后订单才变已取消（退款走 mock 通道，开发环境直接成功）。
> `status`：1=同意，2=拒绝。

### 修改密码（新增）
```
PUT /admin/employee/editPassword
Body: {"oldPassword":"旧密码","newPassword":"新密码"}
```
> 校验旧密码（兼容老 MD5 和新 BCrypt），新密码自动 BCrypt 加盐存储。以当前登录者身份改密（防越权）。

### 其他管理功能
```
菜品管理：起售/停售、改库存
优惠券：创建优惠券 → 顾客下单可抵扣
员工管理：增删改查、启用/禁用、改密码
骑手管理：新增/启用配送员（派送时指派）
```

## 快速故障排查

| 现象               | 解决                               |
| ------------------ | ---------------------------------- |
| 图片裂了           | 后端没重启（图片代理接口没生效）   |
| 各种页面空 / 401   | 登录态失效 → 重新点登录            |
| 客服"连接失败"     | Agent 服务（8000）没启动           |
| 下单还是"待付款"   | 小程序没重新编译（支付接线没生效） |
| 提示"操作过于频繁" | 触发限流，等 1 分钟                |
| 首页返回空白       | 重新编译小程序（onShow 修复）      |
| 管理端 401         | 请求头没带 `token`（不是 Authorization） |
| 派送报"订单状态错误" | 订单id填到Query了（应填Path）或没先接单 |
| 退款后没变已取消   | 后端没重启（退款转取消逻辑没生效） |
| sky-web 打不开     | 没设 `$env:NODE_OPTIONS="--openssl-legacy-provider"` 或没装依赖 |
